# 项目总目标（Goal）

> **版本**：v0.2（2026-08-30）
> 变更记录：v0.1 初始；v0.2 增加 CI 编译、UI 不限屏数、现代化设计

## 项目背景
- 业务场景：当前用户已经部署了 `QuantumNous/new-api`（基于 One API 二次开发的 AI API 中转站）。New API 本身已经实现了「多 key 路由、多 API 路由」等复杂中转能力，但是**只有 Web 端，没有原生安卓客户端**。Web 端在手机上体验差，且 New API 自带的前端 UI 包含了大量用不上的功能（兑换码、收费、订阅、公告、Midjourney 任务面板、deployments 等），不够精简。
- 目标用户：**用户本人**（项目自用），单设备单人使用。技术背景为非开发者（小白），需要 APP 安装即用、配置简单、UI 直观。

## 总目标
做一款**安卓原生 APP**，最终产物是一个**可安装的 `.apk` 安装包**。APP 安装后：

1. **释放并启动 New API 后端服务**（Linux ARM64 ELF 二进制 + SQLite 数据库，整体作为 APP 内部资源）
2. **提供精简的手机端 UI**，仅暴露用户用得上的功能（启停控制 + 必要的查询/配置）
3. **保活后端服务**：后端启动后，APP 尽量保活，确保本地 API 长期稳定可被外部 agent 调用
4. **后端停止后立即释放资源**：停止后不再强制保活，APP 退出后完全释放手机资源（不留后台进程、不耗电）

## 成功标准
- 功能成功标准：
  - 安装 APK 后启动，APP 内可一键启动 New API 后端
  - 启动后 APP 持续保活（前台服务 + 通知），后端服务不退出
  - APP 内可一键停止后端；停止后通知消失、APP 可被系统清理
  - 外部 agent（在同一局域网/同机）可通过 `http://&lt;手机 IP&gt;:&lt;端口&gt;` 调用 New API 的 OpenAI/Claude/Gemini 兼容接口
  - APP 暴露的功能集合：后端启停、状态查看、最小必要的查询/配置（按"UI 极简原则"裁剪）
- 质量成功标准：
  - APK 可在普通安卓手机（arm64，Android 8+）直接安装运行
  - 启动后端后，APP 内存占用 &lt; 250 MB（New API 进程 + APP 自身）
  - 后端响应延迟与原版 New API 一致

## 范围边界（做 / 不做）
- **做**：
  - 安卓原生 APP（Kotlin + Jetpack Compose，**现代化 + 美观 + 流畅**）
  - 内嵌 New API 后端二进制（剥离前端后编译的 Linux ARM64 单文件，含 SQLite）
  - APP 控制后端启停 + 状态查看
  - **APP UI 完整暴露后端所有对自用有意义的功能**（不再硬性限制 6 个屏幕，按功能自然拆）
  - 后端启动时保活（前台服务）
  - 后端停止时立即释放保活
  - **利用 GitHub Actions 云编译**：开发者不搭本地安卓环境，写代码 → push → CI 自动编译 → 自动发布到 GitHub Releases → 用户下载安装测试
  - **CI 出错要迭代修复直到通过**：用 CI 日志定位问题 → 改代码 → 重 push → 循环直到绿
  - **配置备份导入导出**（v0.3 新增）：APP 内提供「导出配置」「导入配置」功能，把本地配置（服务器地址、PAT、渠道配置、端口等）导出成单个文件（JSON），可自行保存/迁移；导入时覆盖本地配置。**导出文件只落在本地存储，绝不上传任何云端**
- **不做**：
  - 修改 New API 后端业务源码（业务逻辑 0 改动；M2 仅改 `main.go` 去掉前端 embed，构建相关）
  - 重新实现 New API 业务逻辑（全靠 New API 后端）
  - iOS 端、PC 端、其他平台
  - 账号云同步、多设备协同
  - 本地搭建 Android Studio / Gradle / SDK
  - 仍不做的 UI 功能（用户用不上 + 后端剥除）：
    - 商业化功能（兑换码、收费、订阅、支付、Stripe、Waffo 等）
    - 部署管理（io.net Deployments）
    - Midjourney / Suno 任务面板
    - 公告、关于、用户协议、隐私政策等"门面"页面
  - UI 入口可做但不强制：复杂 OAuth/2FA/Passkey/Telegram 登录

## 约束条件
- 技术约束：
  - 安卓设备：arm64 架构、Android 8+（API 26+）
  - 目标用户是非开发者：UI 必须极度简化，砍掉所有非必要元素
  - 后端必须剥离前端编译：New API 本身 `//go:embed web/dist`，需要去掉这个依赖，只保留纯 API 服务
  - 二进制必须 CGO 禁用（`CGO_ENABLED=0 GOOS=linux GOARCH=arm64`），否则 Bionic libc 不兼容
  - 数据库：SQLite（用户机器上单设备使用，无需多节点 MySQL/PostgreSQL/Redis）
  - 端口：APP 内固定一个非保留端口（如 13000-13500 区间），不开放公网
- 时间约束：无强交付时间
- 法律约束：遵守 New API 的 AGPLv3 协议
